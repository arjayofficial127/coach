## Outcome

Phase 7 lets the user refine a saved page after capture. Each library or reading-queue card exposes
a trusted editor for its title and description. Saving changes updates only those two frontmatter
scalars in the existing Obsidian Markdown note.

The operation is deliberately metadata-only: it keeps the stable Lattice ID, URL, reading state,
timestamps, desktop association, folder, filename, relative path, and complete Markdown body. This
means manual prose, backlinks, embeds, or other content added in Obsidian is never regenerated by
Lattice's editor.

The update passes through the existing trusted preload boundary, validates a UUID plus bounded
title/description, rejects duplicate or stale identities, rejects links/junctions, detects a
concurrent file-size/mtime change, writes and flushes a same-directory temporary file, then replaces
the original atomically. No website gains access to the API.

## Development workflow

Use `pnpm start`; renderer changes hot-reload and main/preload changes rebuild and restart Electron.
Reinstallation is only needed to test setup or installed behavior. The complete gate is
`pnpm run verify:phase7`.

## Deliberate boundary

Phase 7 does not rename files from edited titles, regenerate note bodies, edit arbitrary Markdown,
delete notes, move saved links between desktops, or implement merge/conflict UX. It also preserves
the deny-by-default browser boundary: no downloads, OAuth popups, extensions, site permissions,
signing, or updates were added.
